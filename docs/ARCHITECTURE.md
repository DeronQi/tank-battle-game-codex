# 架构与行为约定

## 文件职责

| 文件 | 职责 |
|---|---|
| `index.html` | 开始选择、战场、状态栏、关卡工坊与帮助弹窗 |
| `src/main.js` | 固定步长主循环、输入、界面切换、音效、本地存储与工坊交互 |
| `src/engine.js` | 地图生成、寻路、战斗、碰撞、敌军、补给和 AI；不依赖 DOM |
| `src/renderer.js` | Canvas 像素绘制、效果、关卡编辑预览 |
| `src/campaign.js` | 胜利推进与失败重试的状态转换 |
| `src/style.css` | 开始 / 作战布局、移动端、全屏 |
| `server.mjs` | 本地静态开发服务器，只监听回环地址 |

## 战斗模拟

地图为 26 × 26 格，每格 24 像素。渲染通过 `requestAnimationFrame` 驱动，模拟按固定 1/60 秒步长更新；引擎也允许独立运行采样和测试。子弹通过小步进处理碰撞，友军免伤，双方炮弹可以相互抵消。

玩家有独立的生命、火力、护盾、加速与复活状态。敌军类型决定装甲、移动速度、开火间隔和击破分数。玩家耗尽生命或基地被摧毁时判负；清除本关全部敌军时判胜。

## 随机地图

生成分为三步：

1. 按种子选择地形比例，生成尺寸、位置和边角变化的地形斑块。
2. 保留出生区、基地、护墙和小范围的基地前方落脚区。
3. 对未连通的可行走区域寻找代价较低的局部连接，优先清除砖墙，尽量保留钢墙和水域。

所有可行走区域无需先打墙即可互通。生成器不固定清空整行或整列，不检查或刻意破坏直线射界。相同种子在同一版本内可以复现地图；改变生成算法后，相同种子不保证产生历史版本的地形。需要长期保存的地图应导出 JSON。

## AI

AI 使用规则、加权 A* 寻路与短时轨迹预测，无外部模型或 API。

1. **基地安全**：识别即将命中基地的炮弹，先尝试对射抵消；无法开火时安排可达的车体拦截，必要时牺牲生命，优先使用合适的护盾队员。
2. **自身安全**：预测约 0.75 秒内不同移动轨迹的风险，考虑墙体、装填、弹数限制和交叉火力，选择闪避或对射。
3. **主动行动**：寻找可达的射击位置、清除砖墙、绕行钢墙；双 AI 协调目标，并由后方队员维持支援。道具按实际需求、路径耗时和消失时间评估，紧急防御会取消拾取。

轰炸和冻结影响敌军坦克，不能据此假设已发射的炮弹消失。AI 遵循与玩家相同的移动、开火、碰撞和道具规则，仍可能失守。

## 关卡状态

- 胜利：关卡编号加一，新种子生成地图，保留得分及玩家成长；已阵亡队员以至少一条生命重新加入。
- 失败：关卡编号、地图种子及原始地图不变，恢复本关开始时的得分、生命和火力，清空本轮战斗状态。
- 重试次数影响敌军行为随机数，避免完全重复同一条失败轨迹，不改变原始地形。
- AI 演示在结果出现约 3.5 秒后自动执行上述规则；手动模式由结果按钮继续。

## 存储与部署

最高分、音效开关和一张自定义地图存于浏览器 Local Storage。地图 JSON 可导入导出，无云端账户或同步服务。

项目是静态前端，开发服务器不提供业务 API。当前资源路径按网站根目录组织；部署到域名根目录可直接使用，部署到子路径需相应调整资源路径。直接使用 `file://` 打开不受支持。
